# MageCode 2.0 Upgrade & Optimization Roadmap

> **For agentic workers:** This is the MASTER roadmap. Each sub-plan (A–G) must get its own
> detailed implementation plan (superpowers:writing-plans) before execution, then be executed
> with superpowers:subagent-driven-development or superpowers:executing-plans. Do NOT execute
> directly from this document.

**Goal:** Build all MageCode 2.0 services in the current monorepo, using `docs/` as the source
of truth and `/home/gideon/Documents/BKCS/deprecated_magecode` strictly as salvage reference.

**Architecture:** Monorepo (D-23) with 7 services under `services/`, two processing paths —
real-time CES with direct DB access (D-81) and stateless batch SIM/AID/VUL workers (D-80) —
orchestrated by the Laravel api over 6 RabbitMQ queues, files in MinIO, results streamed via
Reverb, observability via Prometheus/Grafana/Loki.

**Tech Stack:** PHP 8.4 + Laravel 13 (see Upgrade U-1), Go 1.26 bare + `shared/go` packages,
Python 3.12 (pika/structlog/torch/transformers), Vue 3.5 + Pinia + Tailwind 4 + shadcn-vue,
PostgreSQL 16 + PgBouncer, RabbitMQ, MinIO, Judge0 CE 1.13.1, Traefik.

## Global Constraints

- **Source of truth**: `docs/technical-design.md`, `docs/database-schema.md`,
  `docs/rabbitmq-schemas.md`, `docs/api-contracts/openapi.yml`, `shared/schemas/*.json`,
  decision logs D-01–D-90. The deprecated prototype NEVER overrides these.
- Monorepo layout per `docs/docker-compose-architecture.md` §9.1: services under `services/`,
  Go workers use `replace github.com/magecode/shared/go => ../../shared/go`.
- SIM/AID/VUL: **no DB access, no MinIO credentials** (D-80, D-85). CES: direct DB with
  **upsert** on `code_execution_results (submission_id, test_case_id)` (D-81).
- All RabbitMQ messages validate against `shared/schemas/*.json`: required `trace_id`,
  `timestamp`, `version: "1.0"`; job messages `additionalProperties: false`, result messages open.
- Logging: JSON to stdout only — `timestamp`, `level` (debug|info|warn|error), `service`,
  `message`, optional `trace_id`/`data`/`error` (D-88). No `fmt.Println`, `dd()`, `console.log`.
- PgBouncer transaction pooling: Laravel needs `PDO::ATTR_EMULATE_PREPARES => true`; pgx needs
  `default_query_exec_mode=simple_protocol` (D-89).
- API base path `/api/v1` with Bearer Sanctum tokens, `{data, meta}` envelope per `openapi.yml`.
- Test-first (v1.0 lesson). No `panic()` for business errors (use `shared/go/apperror`).
- Statuses are lowercase snake_case string enums (D-26); valid values in
  `docs/database-schema.md` §10.
- Source file limit 50KB (D-34); test cases max 50/problem, 1MB each (D-45).
- Never commit `.env`; `deprecated/**` stays gitignored.

## 2. Upgrade & Optimization Decisions (U-1 … U-10)

Deviations/corrections vs prototype and doc inconsistencies to resolve. Flag any change of
these during execution back to this file.

- **U-1 Laravel 13 / PHP 8.4** — D-10's rationale is "latest version"; prototype proves 13
  works. Target `laravel/framework ^13.0`, PHP 8.4, Go 1.26+, Python 3.12+.
  *Docs amended 2026-08-10 (decisions-v3 §7).*
- **U-2 Authorization layer (biggest prototype gap)** — Laravel Policies per model +
  membership-role resolution (`organization_members.role`, `section_members.role`).
  Section = isolation boundary (D-04): every query scoped through membership. Drop unused
  Spatie tables from migration set OR wire Spatie properly — decide in Plan B brainstorm;
  default: **drop Spatie**, roles are already membership columns (docs §3 model).
- **U-3 Route regeneration from openapi.yml** — `/api/v1` prefix, all ~60 documented paths,
  rate limit 10/min on submission endpoints. Openapi is the contract; prototype routes are
  only a naming reference.
- **U-4 MinIO from day one** — `league/flysystem-aws-s3-v3` disk, path
  `submissions/{problem_id}/{submission_id}/{filename}` (D-42/D-77), pre-signed URLs TTL
  **6h** (rabbitmq-schemas §2.6 supersedes D-85's 2h; *docs amended 2026-08-10*).
  Upload validation: 50KB (D-34, prototype's 1MB is wrong) + extension allowlist derived
  from `programming_languages`.
- **U-5 Roles: adopt 5-role model** — openapi.yml includes System Admin; resolved as 5 roles
  (System Admin bootstraps organizations). *Docs amended 2026-08-10 (decisions-v3 §7).*
- **U-6 Postgres-only tests** — migrations use Postgres partial indexes/CHECKs; prototype's
  SQLite test setup can't run them. CI/test uses Postgres (compose service or testcontainers);
  delete `database/database.sqlite` remnants from composer scripts.
- **U-7 Quota under concurrency** — submission count check inside a transaction with
  `SELECT ... FOR UPDATE` (D-36/D-39); port nothing here, prototype never implemented it.
- **U-8 Reverb events** — implement the 4 documented channels/events (openapi.yml:51-58):
  `private-submission.{id}` (`execution.updated`, `execution.completed`),
  `private-section.{id}` (`analysis.progress`, `analysis.completed`) + channel auth in
  `routes/channels.php` using section membership.
- **U-9 SIM completion counter in cache table, not memory** — rabbitmq-schemas §5.3 allows
  in-memory/Redis; we have no Redis and api restarts lose it. Use Laravel `cache` (database
  store) keyed `sim_completion:{analysis_problem_id}`; timeout job (D-82) remains backstop.
  **Refined in D4/D6 (v3 §7, 2026-08-18)**: the value is the *set* of received
  `language_group_index` values, not a count — a counter advances on a redelivered message and
  would close a batch with a group still in flight. And it is an optimisation, not the
  authority: completion is decided from the `analysis_submissions` rows, so a lost key never
  holds a finished batch open.
- **U-10 Metrics endpoints** — each Go worker exposes promhttp `/metrics`; ai-detector uses
  `prometheus-client`; api exposes php-fpm status for the exporter (already scraped per
  `deploy/docker/prometheus/prometheus.yml`).

## 3. Sub-Plans (execution order)

Dependency chain: A → B → C → D → E; F starts after B's auth endpoints exist and tracks the
API; G last. Each sub-plan = separate branch + separate detailed plan file.

### Plan A — Shared Go packages + service scaffolds

**Scope:** Implement the six `shared/go/*` packages (currently 2-line stubs) and create
`services/` scaffolds matching `docs/docker-compose-architecture.md` §9.1.
**Key work:** `rmq` (connect/reconnect with backoff, publish persistent, consume with manual
ack + prefetch option, DLX declaration per D-79e), `db` (sqlx+pgx, `simple_protocol`, pool
config), `storage` (MinIO client: get/put, pre-signed GET), `logger` (slog JSON handler
renaming `time`→`timestamp`, `msg`→`message`, injecting `service`), `config` (env load +
validate), `apperror` (typed errors, no panic). Move workers' module dirs to
`services/<name>/` so the `replace ../../shared/go` path resolves; wire `go.work`.
**Deliverable/verify:** `go test ./...` green in `shared/go`; `go build ./...` in all three
worker scaffolds; a smoke binary publishes+consumes a message against compose RabbitMQ.

### Plan B — api core (docs Phase 2 part 1)

**Scope:** `services/api` Laravel 13 app: auth (Sanctum bearer per openapi), 5-role RBAC +
policies (U-2/U-5), CRUD for Organization/Course/Semester/Section/Problem/TestCase/Tag,
member management + CSV/Excel import + transfer logs, `/api/v1` routes (U-3), migrations +
seeders (salvage matrix), Postgres test setup (U-6).
**Salvage:** models, migrations, requests, resources, tests from prototype per §1.
**Deliverable/verify:** `make migrate && make seed` clean on compose Postgres; `php artisan
test` green incl. ported 51 tests + new policy tests proving section isolation (instructor
L01 gets 403 on L02 resources).

### Plan C — Submission flow + code-executor (docs Phase 2 part 2)

**Scope:** api submission endpoints (editor JSON + multipart upload, U-4 storage, U-7 quota,
`is_outdated`/`testcases_updated_at` D-41), publish to `code-executor` queue (ID-only job);
Go CES service: consume → read test cases/language via DB → download from MinIO → Judge0
`POST /submissions?wait=true` per test case (auth token, limits from problem) → upsert
`code_execution_results` → recount + update `submissions` → publish `result-execution`;
api `result-execution` consumer (artisan command) → Reverb push (U-8).
**Deliverable/verify:** end-to-end demo on `make up` + `make up-judge0`: submit Python
solution → per-test-case rows in DB → WebSocket event received (automated feature test +
manual `make dev-web`-less curl/websocat check).

### Plan D — Analysis orchestration in api (docs Phase 3 part 1)

**Scope:** `POST /problems/{id}/analysis` trigger: scope resolution (`bank_problem_id` auto /
`manual_match_group_id` manual, D-47/D-58), latest-submission-per-student (D-49), re-trigger
`is_latest` transaction (D-53), SIM language grouping + `not_applicable` rules
(rabbitmq-schemas §3.2), pre-signed URLs 6h (U-4), job publishing for SIM/AID/VUL;
`result-analysis` consumer: per-service handlers, `match_type` assignment (D-61), SIM
completion counter (U-9), batch completion + Reverb events (U-8); timeout scheduled job
5min/30min (D-82); analysis read endpoints incl. two-tier similarity visibility (D-05/D-06)
and match-group management endpoints.
**Deliverable/verify:** feature tests with faked AMQP: trigger → correct messages per schema
(validate against `shared/schemas`); inject synthetic results → correct DB rows, statuses,
two-tier filtering by role.

### Plan E — Batch workers SIM / AID / VUL (docs Phase 3 part 2)

**Scope:** three stateless services built on Plan A packages.
`plagiarism-checker`: consume language-group job → download all files → Dolos CLI → parse
pairs (ordered a<b, regions pipe format) → publish result. Prefetch 1, `DOLOS_TIMEOUT=300`.
`ai-detector`: pika consumer, CodeBERT (`microsoft/codebert-base`) inference → probability;
`not_applicable` for unsupported language; model cache volume. Prefetch 3.
`vuln-scanner`: CodeQL CLI (db create + analyze), severity mapping, tmpfs workspace,
`VUL_CODEQL_TIMEOUT=600`. Prefetch 3.
**Deliverable/verify:** per-service integration test with fixture code files → result message
validates against `result.analysis.v1.schema.json`; full pipeline demo through compose
`--profile analysis`.

### Plan F — web frontend (docs Phases 2–4 UI)

**Scope:** fresh Vue 3 app in `services/web` using prototype's dependency set: auth flow,
role-based dashboards (D-09), section/problem management, Monaco submission editor +
real-time execution results (Echo), analysis trigger UI (SIM+AID checked, VUL unchecked,
D-24), similarity visualization with two-tier gating + side-by-side highlight regions,
problem bank (clone/publish/versions/approve), notifications, exports.
**Deliverable/verify:** `make dev-web` against `make dev-api`; Playwright smoke: login →
submit → see live result; instructor triggers analysis → sees progress → similarity view.

### Plan G — Production readiness (docs Phase 5)

**Scope:** wire app metrics (U-10), Grafana dashboards/alerts already in `deploy/`, security
pass (validation coverage, authz matrix test per role×endpoint, upload hardening), load test
(500 concurrent submissions), deployment guide, optional GitHub Actions with path filters.
**Deliverable/verify:** load-test report; alert rules fire in staged failure drills;
`docker compose --profile full up` + judge0 runs the whole platform.
